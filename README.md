# Meridian Retail Support-Draft Review Tool

A small classroom demo. It drafts a customer support reply for one
fictional case at a time, using only the facts in `cases.json` and the
rules in `policy.md`, and prints it for a human reviewer. It supports two
interchangeable model backends: a **local** model via
[Ollama](https://ollama.com) (no account needed), or a **cloud** model via
[OpenRouter](https://openrouter.ai) (needs a free API key).

This tool **only prints text**. It never sends messages, approves refunds,
or changes any records (policy P4). A person must review every draft
before acting on it.

## Files

- `policy.md` — the drafting policy the model must follow.
- `cases.json` — three fictional support cases (C1, C2, C3).
- `app.py` — CLI entry point. Loads the chosen case and the policy, calls
  the configured model backend, validates its response, and prints three
  labelled sections.
- `setup_env.py` — interactively asks which backend to use and prompts
  for that backend's settings, then writes a project-local `.env`.
  OpenRouter's API key uses hidden input and is never printed; Ollama has
  no secret to hide.
- `.env.example` / `.env` — where backend settings live (`.env` is
  gitignored).
- `requirements.txt` — pinned Python dependencies.
- `demo_outputs.json` — prerecorded synthetic results used only by
  `--offline-demo`. Not generated by calling a model.
- `test_app.py`, `test_setup_env.py` — unit tests (no network calls, no
  Ollama installation or OpenRouter account required to run them).

## Setup

Pick a backend by setting `APP_MODEL_BACKEND` in `.env` (`ollama` is the
default if unset):

### Option A — Ollama (local, no account needed)

1. Install Ollama (macOS: `brew install ollama`, or download from
   [ollama.com](https://ollama.com)) and make sure it's running:

   ```bash
   ollama serve   # if it isn't already running as a background service
   ```

2. Pull a model:

   ```bash
   ollama pull llama3.2
   ```

### Option B — OpenRouter (cloud, free-tier models)

1. Create an account and API key at [openrouter.ai](https://openrouter.ai/keys).
2. Pick a current free model id from
   [openrouter.ai/models?max_price=0](https://openrouter.ai/models?max_price=0)
   (format: `provider/model-name:free`) — free models rotate over time, so
   check what's currently listed rather than assuming a specific one.

### Then, either way

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup_env.py
```

`setup_env.py` asks which backend to use, then only the settings that
backend needs, and writes them into a local `.env`.

## Running

```bash
python app.py --case C1
```

`--case` is required and must be `C1`, `C2`, or `C3`. Every run prints
three sections: `SUPPLIED FACTS`, `SUPPLIED POLICY`, and
`DRAFT RESULT FOR HUMAN REVIEW` (`review_status`, `draft_reply`,
`evidence_refs`, `missing_information`).

Two flags bypass the live model entirely, for demoing without either
backend configured:

```bash
python app.py --case C1 --offline-demo       # loads a prerecorded result
python app.py --case C1 --simulate-timeout   # shows the safe unavailable state
```

If `C2` is selected (its `delivery_date` is missing), the app never calls
the model at all — it returns a deterministic "please provide the delivery
date" result per policy P2.

If the real call to the configured backend fails (not running/reachable,
model not found, timed out, missing config) or the model returns something
that doesn't match the required JSON schema, the tool shows the same safe
unavailable state (`review_status: UNAVAILABLE`, empty draft) with a
manual-fallback message — never a traceback or a stale draft.

**Backend selection:** `APP_MODEL_BACKEND` (`ollama` or `openrouter`,
default `ollama`).

- Ollama: `APP_OLLAMA_HOST` (default `http://localhost:11434`),
  `APP_OLLAMA_MODEL` (default `llama3.2`).
- OpenRouter: `APP_OPENROUTER_API_KEY` (required, no default),
  `APP_OPENROUTER_MODEL` (required, no default — pick a current free
  model id).

## Testing

```bash
pytest
```

Tests use fake model functions and fake input readers throughout — no
real Ollama or OpenRouter calls are made, and neither needs to be
installed/configured to run them. They cover both backends' client and
model-call dispatch, a successful draft, invalid model output, a
simulated provider timeout, a missing-configuration failure, the
deterministic missing-delivery-date path, all three input files,
offline-demo output, and `setup_env.py`'s `.env` writing for both
backends.
