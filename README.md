# Meridian Retail Support-Draft Review Tool

A small classroom demo. It drafts a customer support reply for one
fictional case at a time, using only the facts in `cases.json` and the
rules in `policy.md`, and prints it for a human reviewer.

This tool **only prints text**. It never sends messages, approves refunds,
or changes any records (policy P4). A person must review every draft
before acting on it.

## Files

- `policy.md` — the drafting policy the model must follow.
- `cases.json` — three fictional support cases (C1, C2, C3).
- `app.py` — CLI entry point. Loads the chosen case and the policy, calls
  the model, validates its response, and prints three labelled sections.
- `setup_env.py` — interactively prompts for the API key (hidden input)
  and model, and writes a project-local `.env`. Never prints the key.
- `.env.example` / `.env` — where the API key and model live (`.env` is
  gitignored).
- `requirements.txt` — pinned Python dependencies.
- `demo_outputs.json` — prerecorded synthetic results used only by
  `--offline-demo`. Not generated by calling a model.
- `test_app.py`, `test_setup_env.py` — unit tests (no network calls).

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python setup_env.py
```

`setup_env.py` will ask for your Anthropic API key (input is hidden) and
the model to use (press enter to accept the default,
`claude-haiku-4-5-20251001`), then write both into a local `.env`. The key
is never printed to the terminal.

## Running

```bash
python app.py --case C1
```

`--case` is required and must be `C1`, `C2`, or `C3`. Every run prints
three sections: `SUPPLIED FACTS`, `SUPPLIED POLICY`, and
`DRAFT RESULT FOR HUMAN REVIEW` (`review_status`, `draft_reply`,
`evidence_refs`, `missing_information`).

Two flags bypass the live API entirely, for demoing without a key or
network access:

```bash
python app.py --case C1 --offline-demo       # loads a prerecorded result
python app.py --case C1 --simulate-timeout   # shows the safe unavailable state
```

If the real API call fails or the model returns something that doesn't
match the required JSON schema, the tool shows the same safe unavailable
state (`review_status: UNAVAILABLE`, empty draft) with a manual-fallback
message — never a traceback or a stale draft.

The app reads its key only from `APP_ANTHROPIC_API_KEY` and its model only
from `APP_ANTHROPIC_MODEL` (default `claude-haiku-4-5-20251001`); it never
reads or sets the global `ANTHROPIC_API_KEY`.

## Testing

```bash
pytest
```

Tests use a fake model function and fake input readers throughout — no
real API calls are made. They cover a successful draft, invalid model
output, a simulated provider timeout, all three input files, offline-demo
output, and that `setup_env.py` writes the key to `.env` without ever
printing it.
